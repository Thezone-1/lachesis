# v0.2 — From Attendance to Yield

Written: 2026-07-12 · Status: planned, not started · Target: next session

## Problem

v0.1 measures attendance (foreground time per app). Attendance is farmable —
leave VS Code focused, run repetitive AI tasks, look busy (the "Kiro board
farmer" case). Productivity must be scored as **yield**: outcomes per unit of
focused attention, never raw volume.

## Principles (bake into every metric)

1. **Never score volume.** Hours, tokens, samples, keystrokes — anything that
   grows by doing *more* gets farmed (Goodhart). Only ratios and outcomes.
2. **Outcomes anchor the score.** Artifacts (commits, files changed) during
   focused time are the ground truth that activity was real.
3. **Self-budget framing.** Lacheisis is a self-tracker: time is an allotment
   to spend well, not a score to maximize. No leaderboard semantics, ever.
4. **Gaming leaves a signature.** Farmed activity is low-entropy (looping
   titles) and metronome-uniform. Surface it, don't reward it.

## Four layers (build order)

### 1. Category rules engine — `categories.go`

Classify every sample into `productive | neutral | distracting`.

- Rule = `{match: app | title, pattern: substring (case-insensitive), category}`.
  Title rules evaluated **before** app rules (chrome on "youtube" is
  distracting even though chrome could be neutral); first match wins;
  unmatched → neutral.
- Rules live in `config.json` under `"rules": [...]`. Ship defaults for this
  machine: `code`, `windowsterminal`, `goland` → productive; titles containing
  `youtube`, `netflix`, `twitter/x.com` → distracting; `stack overflow`,
  `pkg.go.dev`, `github` titles → productive.
- New command: `lacheisis classify <app|title> <pattern> <category>` appends a
  rule without hand-editing JSON.

### 2. Focus blocks & fragmentation — `blocks.go`

Sessionize the sample stream (all computable from existing JSONL):

- **Block** = contiguous run of samples in the same app; a gap or app change
  ≤ 2 samples (10s) does NOT break a block (alt-tab glances are noise).
  Idle samples always break blocks.
- **Deep-work block** = block ≥ 25 min in a productive-category app.
- **Metrics per day**: deep-work total + block count, longest streak,
  context switches per active hour, **title entropy** per block
  (unique titles / samples — a farmer looping the same task scores near 0;
  real work evolves through changing titles).

### 3. Yield: artifact linkage — `gityield.go`

Anchor focus to output:

- Config `"repos": ["D:\\code\\AI\\lacheisis", "D:\\code\\AI\\trainpulse", ...]`.
- For the report day: `git log --since <day 00:00> --until <day 24:00>
  --author=<user> --pretty=%H|%ct|%s --shortstat` per repo (read-only).
- Attribute each commit to the deep-work block containing (or nearest
  preceding, ≤30 min) its timestamp.
- **Yield = commits + files-changed per deep-work hour.** Deep-work hours with
  zero artifacts across all repos aren't zero-value (thinking/reading is real)
  but they don't add yield — the score rewards conversion, not presence.

### 4. Daily score & report v2 — extend `report.go`

Score 0–100, all components ratio-based (weights in config, defaults below):

| Component | Definition | Weight |
|-----------|-----------|--------|
| Focus ratio | productive time / active time | 35 |
| Depth | deep-work time / productive time | 25 |
| Cohesion | 1 − min(1, switches-per-active-hour / 30) | 15 |
| Yield | min(1, artifact-linked deep-work hours / deep-work hours) | 25 |

Farmer signature check (reported, not silently punished): flag any deep-work
block with title entropy < 0.05 or metronome-regular switching as
`⚠ low-entropy block — looping?`.

Report layout: header (score + verdict line), per-app bars (as v0.1, now
color-tagged by category), deep-work blocks timeline with linked commits,
Atropos allotment cuts, warnings.

## Explicitly out of scope for v0.2

- Live Atropos toasts, auto-start on login, weekly trends (v0.3 candidates)
- Token/Claude usage ingestion (possible later via [[ccyield]] data — same
  yield-not-spend framing)
- Any SQLite migration — JSONL still sufficient

## Testing

Synthetic fixtures in `testdata/`: `farmer.jsonl` (uniform 6h in one app, one
looping title, no commits) vs `deep.jsonl` (3 deep blocks, evolving titles) —
farmer must score materially lower despite more "productive" hours. Unit
tests: rule precedence, block gap tolerance, entropy, commit attribution,
score bounds.

## Build order (single session, roughly)

1. `categories.go` + config rules + defaults + `classify` command
2. `blocks.go` sessionizer + metrics + entropy
3. `gityield.go` commit scan + attribution
4. Score + report v2 rendering
5. Fixtures + tests (`go test ./...`), dogfood against today's real data
